# 11.5 AI 运行手册与上线检查

## 运行依赖

- PostgreSQL：业务数据、AI 会话、消息、引用和反馈的权威存储。
- Redis：现有应用健康检查依赖；11.3 单实例流式通知不使用 Redis 锁或队列。
- DeepSeek Harness：会话创建、提示词入队、事件 Mux、历史补偿和取消。
- 知识库索引：混合检索优先，Embedding 不可用时自动降级为关键词检索。

## 配置检查

启动前确认 API 可访问 Harness 地址，默认地址为 `http://127.0.0.1:3080`；events.mux 默认使用 `ws://127.0.0.1:3080/api/events.mux`，可通过 `DSH_EVENTS_URL` 覆盖。模型和 Provider 继续由 `DSH_PROVIDER`、`DSH_MODEL` 控制。

禁止把密钥、完整提示词、跨项目业务数据或用户输入原文写入日志。AI 第一版只读，不允许通过回答链路修改项目、任务、风险、协调事项、审批或知识库数据。

## 故障排查

### Embedding 或向量服务不可用

现象：RAG 返回结果标记 `degraded: true`，检索模式为 `keyword`。处理：检查向量服务健康和模型维度；关键词降级期间继续验证引用是否来自当前项目和当前版本，不要手工把其他项目文档加入 Prompt。

### Harness 不可用或生成失败

现象：助手消息进入失败状态并保留可重试信息。处理：检查 Harness 地址、Provider、模型和 events.mux；确认会话历史；使用页面“重试”，不要重复点击发送造成新的请求。

### 流式连接断开

客户端重新连接 SSE 并从数据库历史恢复；Mux 客户端重连后通过 Harness `session.history` 补偿活动会话。检查 API 是否发生重启。当前 11.5 仍是单 API 实例设计：进程内事件通知不是跨实例广播。

### 取消后出现迟到事件

取消应先写入终态，再尽力调用 Harness cancel。数据库终态优先，迟到完成事件不应覆盖已取消消息。若状态异常，保留消息 ID、会话 ID 和 Harness event seq 供排查，不删除历史消息。

## 观测指标

发布评测至少记录：

- 检索命中率、引用覆盖率和无证据问题的拒答率。
- 首字时间（请求 202 到第一个 delta）、总耗时和流式失败率。
- Embedding 降级次数、Harness 错误率、取消成功率和重试成功率。
- 跨项目访问拒绝数、提示注入检测数、反馈 helpful/unhelpful 比例。

指标应按项目和请求 ID 聚合，避免记录问题全文；敏感输入只保留必要的脱敏摘要。

## 上线步骤

1. 执行 `pnpm db:migrate`。
2. 执行 `pnpm verify:11.5`。
3. 确认 API、数据库、Redis、Harness 和知识库健康检查均正常。
4. 在一个测试项目中验证：发送、流式首字、引用展开、来源定位、下载、停止、重试、复制和反馈。
5. 验证切换项目后会话、文档、引用和反馈不串数据。
6. 观察错误率、降级次数和 SSE 重连情况后再扩大使用范围。

## 已知边界

- 当前流式事件通知为单 API 实例内存实现；水平扩展需要 Redis Pub/Sub 或其他跨实例广播。
- Harness 已接收请求后 API 进程突然退出时，不能安全推断是否应自动重新提交；不能无条件重放以避免重复生成。
- 当前评测是 smoke/固定用例，不替代人工评审和正式模型质量评测。
- Vite 构建仍可能报告 chunk size warning，该告警不阻断构建，但应纳入后续性能专项。
