# 项目文档小兔

## 适用范围

当用户提供会议纪要、商机表、实施计划、阶段汇报、周报、方案、邮件、验收材料或其他项目文件，并要求按项目归类、分析项目进展、整理卡点、提出下一步计划、生成部门整体汇报或单项目专项材料时，使用本 Skill。

本 Skill 与 `openclaw-project-management-center` 完全独立。不得修改、覆盖、调用或复用其脚本、模板、历史文件、输出目录、状态口径和数据文件。

## 输出范围

每次执行先识别用户范围：

- `scope=portfolio`：所有项目整体情况；
- `scope=project`：一个具体项目；
- `scope=selection`：用户指定的多个项目。

用户未明确范围时，询问本次输出所有项目整体情况，还是某一个具体项目的专项情况。上一次输出的范围不自动延续到本次。

## 材料归集

递归扫描用户指定目录，记录文件路径、文件类型、可识别日期、材料类型、候选项目和归类置信度。支持 `.docx`、`.xlsx`、`.xls`、`.pdf`、`.pptx`、`.txt`、`.md`。

原始材料采用只读方式处理：不移动、不重命名、不覆盖。分类结果写入独立目录，例如：

```text
project-materials-catalog/
  catalog.json
  项目材料归类索引.md
  [项目显示名]/
    会议纪要提取文本/
    商机明细.csv
    计划表引用清单.csv
```

项目主键优先级：

1. 文件内部的明确项目名称；
2. 实施计划中的“项目总览—项目名称”；
3. 商机表中的“项目名称”；
4. 会议标题、客户/项目集和正文中的唯一项目组合；
5. 文件名推断只能作为候选，必须标注“文件名推断”。

一份材料涉及多个项目时建立多重引用；无法可靠归属时进入“待确认材料”，不得强行归类。商机表中每个有明确项目名称的记录都可作为独立项目范围，不得全部归入“其他商机”。

不得默认合并存在业务关联的项目：AI+纪检监察平台与纪委 AI NAS、AI+企业服务与龙 i 企、AI 龙岗一期与二期均需保留独立名称和证据关系，只有材料明确说明建设范围相同时才建立合并关系。

## 事实与证据规则

每条事实按“项目—事项—事实—时间—状态—责任方—证据位置”记录。证据位置使用：`文件名｜页码/段落标题/Sheet/原始行号`。

来源分层：

1. 签字验收、正式合同、审批/采购凭证、正式发文：高可信事实；
2. 正式会议纪要、阶段汇报、周报和负责人明确进展：实际进展事实；
3. 商机表：客户关系、商机阶段、商务计划和预期，不等同于交付完成；
4. 实施计划表：计划基线，不等同于实际完成；
5. 文件名推断：候选线索。

同一事项出现冲突时，同时保留双方口径，使用“材料存在差异，待项目组确认”。没有证据定位的内容只能写为“待核实”或“目前材料不足，待补充”。

每个项目必须回答四个问题：

1. 当前进展是什么：已形成什么成果，正在推进什么，处于什么阶段；
2. 当前卡点是什么：哪些事项阻碍下一步，影响是什么；
3. 下一步安排是什么：任务、目标时间、责任方、交付物；
4. 需要谁协调什么：责任方、协同方、决策事项和期望时间。

正文不以任务数量、表格数量或完成率作为主线。只有用户明确要求统计时，才在附注或附件中呈现数量和比例。

## Grounded Copy 表达规则

所有面向用户的正文、标题、摘要、判断、建议和 Word 内容使用事实化表达。每个判断写明主体、动作和具体对象，优先附时间、数量、责任方或证据。

推荐写法：

- “项目建议书已通过项目审核科室审核，当前进入局内审批环节。”
- “采购请示和政务云部署影响产品试用与第一阶段验收。”
- “会议纪要记录了两个已明确场景：招投标监督和集体‘三资’监督。”

避免空泛赞美、对比式表达、夸张词和无依据的绝对判断，例如“全面领先、赋能升级、打造标杆、强力推进、整体顺利、无卡点、全部完成、确保完成”。将抽象判断改写为主体、动作、对象、时间和证据明确的句子。

不得使用“我们相信、业内普遍认为、相关领导高度认可”等未注明来源的泛化归因。保留有行动意义的限制性表述，例如“目前缺少现场环境信息”“该事项不属于已验收成果”“项目暂未形成正式计划基线”。

## 领导汇报材料结构

默认使用正式、客观、先总后分的阶段工作汇报结构：

```markdown
# [部门/项目名称]项目进展情况汇报

（[汇报周期或材料截止日期]）

## 一、总体情况

[概括业务主线、当前阶段、已经形成的成果和主要关注事项。]

## 二、重点项目推进情况

### （一）[项目名称]

#### 当前进展
[已完成事实、正在推进事项和当前阶段。]

#### 当前关注事项
[卡点、风险、依赖、材料差异和影响。]

#### 下一步安排
[任务、时间、责任/协同方和交付成果。]

## 三、需重点关注和协调的事项

### （一）[协调主题]
[问题、影响、建议措施和责任方。]

## 四、下一阶段工作重点

[按优先级归纳整体安排。]
```

- `portfolio`：覆盖所有纳入项目。按业务主线和项目阶段组织，资料不足的项目单独标记；商机项目归入前期商机及潜在项目，不与交付项目混写；
- `project`：只写指定项目及其子项目、业务线或工作包；
- `selection`：只写用户指定项目，并在开头说明范围。

## Word 输出

用户要求 Word 时生成 `.docx`：标题居中，正文仿宋，一级和二级标题黑体，设置页眉页脚，保持用户提供的标题层级和段落顺序。原始材料保持只读。输出使用独立名称和目录，不写入 `openclaw-project-management-center` 的输出目录。

## 质量门禁

- [ ] 已按本次指定范围输出；
- [ ] 原始材料没有移动、重命名或修改；
- [ ] 会议纪要、商机表、计划表和阶段汇报已建立来源关系；
- [ ] 每个项目均回答当前进展、卡点、下一步和协调事项；
- [ ] 商机预期与交付事实没有混写；
- [ ] 冲突口径没有被静默合并；
- [ ] 重要判断能回查文件名和位置；
- [ ] 正文使用主体、动作和具体事实，避免空泛赞美、对比式表达和夸张词；
- [ ] 没有读写或改动 `openclaw-project-management-center` 的文件、目录、脚本、模板和历史数据。
